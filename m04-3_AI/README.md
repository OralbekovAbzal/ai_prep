# m04-3 · Спецификация, ИИ и тесты

Упражнение на цикл, по которому сейчас пишут код в AI-командах: **спецификация → тесты → реализация от AI-ассистента → ревью и проверка**.

## Задача

Функция `parse_brief(text) -> dict` разбирает бриф пользователя для сервиса генерации AI-видео и достаёт из него три вещи:

| Ключ | Тип | Что это |
|---|---|---|
| `duration` | `int \| None` | длительность ролика в секундах |
| `aspect_ratio` | `str \| None` | формат кадра: `"9:16"`, `"16:9"` или `"1:1"` |
| `keywords` | `list[str] \| None` | содержательные слова для поиска стилей и движений камеры |

Контекст: бриф приходит в API сервиса генерации. Длительность нужна для расчёта стоимости в кредитах, формат передаётся в модель (она понимает только три значения), а ключевые слова идут в поиск по библиотеке стилей. Если чего-то в брифе нет, парсер возвращает `None`, а переспрашивает пользователя уже сайт.

## Как делал

1. **Спецификация** — сам: типы, правила (минуты переводятся в секунды, «вертикальное» → `9:16`, «горизонтальное» → `16:9`, при двух упоминаниях берётся первое) и крайние случаи (пустая строка, нет данных, числа словами).
2. **Тесты на pytest** — сам, **до** реализации.
3. **Реализация** — отдал только спецификацию, без тестов, AI-ассистенту (Claude Opus 5.5, среднее усилие) в отдельном чате. Код функции в этой папке написан ассистентом.
4. **Проверка** — прогнал тесты, прочитал код и проверил функцию на брифах, которых не было в тестах.

## Где ассистент ошибся и как я это нашёл

Все исходные тесты прошли с первого раза. Ошибки нашлись, когда я прочитал код и проверил функцию на брифах вне тестов. На каждую ошибку добавлен тест.

**1. Принимает форматы, которых модель не поддерживает.**
`parse_brief("видео 4:3 про банк")` → `"aspect_ratio": "4:3"`.
Ассистент сам добавил список «известных» форматов: `4:3`, `21:9`, `4:5` и другие. В спецификации перечислены только три формата, которые понимает модель. Нашёл при чтении кода: в нём лежал отдельный список `_KNOWN_RATIOS`.

**2. Слово-паразит попадает в ключевые слова.**
`parse_brief("Сделай, пожалуйста, короче, видео 15 сек, вертикальное, неоновый город ночью")` → в `keywords` есть `"короче"`.
Список стоп-слов ассистент составил сам, и он неполный. В спецификации было «только содержательные слова», но без точного списка — эту часть ассистенту пришлось додумывать. Нашёл, проверив бриф с разговорными словами.

**3. Не понимает сокращение «с» через пробел.**
`parse_brief("ролик на 15 с")` → `"duration": None`.
Слитное `"15с"` функция распознаёт, а `"15 с"` с пробелом — нет. Нашёл, проверяя разные способы записать одну и ту же длительность.

## Что понял

- **Где спецификация точная, ассистент сделал хорошо.** Минуты, числа словами, «полминуты», «вертикальное», пустая строка — всё по спеке.
- **Где в спецификации дыра, ассистент заполняет её сам,** и не всегда так, как нужно: список форматов, список стоп-слов. Каждая такая дыра — будущий баг.
- **Зелёные тесты ещё не значат, что код правильный.** Все три ошибки прошли мимо исходных тестов. Их поймало чтение кода и проверка на данных вне тестов.
- **Тест может ошибаться сам.** Один мой тест сначала упал из-за опечатки в ожидаемом слове («кэшбек» вместо «кешбэк»), а не из-за кода. Когда тест падает, сначала проверяю сам тест.

## Запуск

```bash
python -m pytest -v
```
