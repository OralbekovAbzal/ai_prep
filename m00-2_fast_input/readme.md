# Скорость чтения ввода в Python

Сравнение трёх способов читать большой ввод из stdin.

## Данные

`create_file.py` генерирует файл `nums.txt`: в первой строке количество чисел,
дальше около 10 миллионов случайных чисел от 1 до 1 000 000, по одному на строку.

```bash
python3 create_file.py > nums.txt
```

## Версии

Все три считают сумму чисел и отличаются только способом чтения:

| Файл | Способ чтения |
|---|---|
| `ver_1.py` | `input()` в цикле |
| `ver_2.py` | `sys.stdin.readline()` в цикле |
| `ver_3.py` | `sys.stdin.read()` целиком, потом `split` |

Запуск с замером времени:

```bash
time python3 ver_1.py < nums.txt
```

## Результаты

Все версии выдали одинаковую сумму: `5000928394581`.

| Способ | Время |
|---|---|
| `input()` | 5,46 с |
| `sys.stdin.readline()` | 1,01 с |
| `sys.stdin.read()` | 0,92 с |

MacBook Air M4, Python 3.15.

## Вывод

`input()` примерно в 5–6 раз медленнее: на каждый вызов он делает лишнюю работу.
На live coding с большим вводом лучше брать `sys.stdin.read()` или `sys.stdin.readline()`.
