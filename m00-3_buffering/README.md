# Буферизация вывода и коды выхода

Скрипт `step.py` печатает числа от 0 до 4 с паузой в 1 секунду,
а затем завершается с кодом из аргумента командной строки.

```bash
python3 step.py 0   # выход с кодом 0
python3 step.py 1   # выход с кодом 1
```

## Буферизация

| Команда | Что видно |
|---|---|
| `python3 step.py 0` | строки появляются по одной, раз в секунду |
| `python3 step.py 0 \| cat` | 5 секунд пусто, потом все строки разом |
| `python3 -u step.py 0 \| cat` | снова по одной |
| `print(i, flush=True)` + `\| cat` | снова по одной |

**Почему так.** Когда stdout идёт в терминал, Python отправляет каждую строку сразу.
Когда вывод идёт в пайп, файл или Docker, Python копит его в буфере и отправляет блоками —
так быстрее, но сообщения появляются с задержкой.

**Как лечится:**
- `flush=True` — сразу отправить конкретную строку;
- `python -u` — отключить буферизацию для всей программы;
- `PYTHONUNBUFFERED=1` — то же через переменную окружения, обычно её ставят в Dockerfile;
- `logging` пишет в stderr, а stderr не буферизуется блоками.

## Код выхода

```bash
python3 step.py 1
echo $?            # 1
```

`0` — успех, любое другое число — ошибка. На код выхода смотрят Docker, CI и скрипты.

`echo $?` показывает код **последней** команды. В `python3 step.py 1 | cat`
это будет код `cat` (0), а не скрипта. Коды всех команд в пайпе показывает
`echo $pipestatus` (zsh) или `echo ${PIPESTATUS[@]}` (bash).
